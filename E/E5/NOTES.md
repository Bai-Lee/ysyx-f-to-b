# E5：minirv实现与依据

依据为官方v26.07 E5原文及其指定的2024-04-11版RISC-V非特权手册。原文实际有7个编号问题，任务矩阵摘要称“九问”是摘要误差；以下覆盖原文全部问题，不补造题目。

| 原文问题 | 答复 |
|---|---|
| RV32I章节、PC宽度 | 第2章；RV32中PC为32位，按字节寻址。本节minirv复位PC=0，E6平台再改为0x80000000。 |
| GPR数量与宽度 | RV32I有32个32位GPR；RV32E有16个32位GPR，minirv采用后者。 |
| x0与sISA R0 | x0恒为0，写入结果丢弃；sISA R0可写。向x0执行load仍须完成访存及其可见副作用。 |
| 指令宽度与基本格式 | 本范围固定32位、IALIGN=32。四种基础格式R/I/S/U，B/J是立即数编码变体；未实现C压缩指令。 |
| 寄存器索引位数 | 指令中仍保留5位索引。RV32E只允许x0–x15，x16–x31编码保留，不能偷偷截断高位使其别名到低寄存器。 |
| add格式 | R型：funct7=0000000、funct3=000、opcode=0110011；rd、rs1、rs2的位置依次为11:7、19:15、24:20。 |
| RV32E区别 | 第3章说明其使用相同编码，主要差异是只提供16个GPR。 |

已提取并实际查看PDF页42、47、50、57的图表（对应正文23、28、31、38页）；原文件和页级证据见手册索引（原完整交付引用：`../../artifacts/E5/manual/index.json`）。另注意：课程概述写RV32I为42条，链接的2024版手册明确写40条unique instructions；本实现遵守课程明确列出的8条，不据该数量概述擅增指令。

## 指令与存储契约

| 指令 | opcode | funct3/额外条件 | 语义要点 |
|---|---|---|---|
| addi | 0x13 | 0 | rs1加符号扩展imm12，取低32位 |
| add | 0x33 | 0，funct7=0 | 两寄存器相加，模2^32 |
| lui | 0x37 | U型 | imm20置于高20位，低12位清零 |
| jalr | 0x67 | 0 | 用旧rs1加符号扩展imm12，清目标bit0，rd接收旧PC+4 |
| lw | 0x03 | 2 | 本EEI采用小端，读取4字节，要求字对齐 |
| lbu | 0x03 | 4 | 取地址所指字节，零扩展到32位 |
| sw | 0x23 | 2 | S型imm12为31:25与11:7拼接；写4字节 |
| sb | 0x23 | 0 | 写rs2低8位，仅对应字节选通 |
| ebreak | 0x00100073 | 精确匹配 | 本课程仿真结束约定；不声称实现完整特权异常/调试体系 |

ISA的地址单位是8位字节，word则为32位。手册允许EEI指定端序，本工程明确选择little-endian。地址加法按32位回绕；DUT保留完整地址，不截断高位。数据访存中的LW/SW不对齐不属于本课支持范围，本实现明确失败且不产生写副作用，不声称实现全部EEI异常。JALR清bit0并不代表可以清bit1，未启用C时半字对齐跳转仍被拒绝。

存储器行为模型以对齐的32位总线读取，写入根据4位mask逐字节更新。额外独立验证了全部16种mask，包括0和0xf，检查相邻字节不受破坏。LBU在RTL内选择字节并零扩展，C参考则直接读取一字节；两种路径不共用字节选择表达式。

## 结构与DPI

`minirv_regfile`负责16个GPR；`minirv_decode`涵盖译码、组合执行及访存格式；`minirv_single`负责PC、提交和写回；`npc_sim`是仿真专用的外层DPI存储模型。后续综合只选择可综合DUT，不把DPI、主机内存或打印混入芯片。

所有DUT状态只在posedge更新。`pmem_read`是可重复求值的窥视接口；真正的load事务另在提交边沿确认，store及ebreak也仅在有效执行边沿发生。这样可避免组合求值重复写设备或重复消耗随机状态。四个额外停机时钟和同电平重复eval用于核验停止后没有额外提交、写入或ebreak通知，这些探测时钟不计入程序性能周期。

官方DPI add示例已运行，另用正负数和边界参数检查返回值；错误C函数版本被拒绝。运行器通过生成的DPI头文件检查ABI。正常训练程序a0可期望为30，标记EXPECTED_TRAP；E6的标准GOOD_TRAP约定仍是a0=0。

## 真实验收

- 官方六指令程序的路径为0→4→16→20→8→12，a0=30；原循环版按请求步数观察，替换halt位置的ebreak版自动停止。
- addi覆盖-2048、-1、0、2047；验证写x0丢弃、加法回绕和lui。
- jalr覆盖rd=rs1、奇地址bit0清零和无C时的bit1对齐错误。
- 存储用0x12345678验证字节序，部分写入后得到0x90abcdef，邻字保持；补充读取高位为1的字节，避免LBU错误符号扩展漏检。
- 固定种子260705的混合程序共6417次有效提交，包含八条核心指令、间接跳过错误指令、读写混合。每个提交由C11独立模拟器、RTL和独立Python模型逐寄存器/PC核对。
- 4组保留寄存器、非法编码及不对齐输入被明确拒绝。6种真实编译错误变体覆盖符号扩展、x0、jalr低位、LBU、SB写掩码和重复ebreak。

第一次故障注入发现LBU测试原先只读出0x12/34/56/78，无法区分零扩展和符号扩展。增加0x90/ab/cd/ef读回后，符号扩展故障立即被检出；没有删掉这个反例。

早期独立C轨迹还暴露镜像加载问题。探针实际记录：calloc后未装载区域为0，但向1MiB缓冲区发起读请求并仅返回28496字节后，余区出现非零值。GDB与重复运行也保留了证据。修复采用文件实际长度读入、检查短读并显式清零余区，全部三方验证重新通过。未确定更底层C库/WSL行为的原因，不将它误称为CPU语义错误或已证明的内核缺陷。活动轨迹现在先写Linux ext4，验证后复制到交付区，并保存输出快照及摘要。

本实现是课程minirv教学子集，不是完整RV32I/RV32E合规处理器；没有用额外硬件指令绕过八指令限制。结果为本地数字仿真结论，不涉及实体时序、PPA或官方考试。

## 10–13：循环、参数与分支

`for (初始化; 条件; 更新)` 的初始化可以是表达式或声明，条件省略等价于真，更新是表达式；循环体可以是块。逗号运算符按左到右求值，结果是右操作数，故可以用 `i++, j--` 同步推进两个变量。它不同于参数列表中的逗号分隔符。短路 `&&` 在左侧为假时不执行右侧，`||` 在左侧为真时不执行右侧；`!` 产生逻辑否定，不能用位运算 `&`、`|` 替代并期待相同求值行为。[GNU C 说明](https://www.gnu.org/software/c-intro-and-ref/manual/html_node/Comma-Operator.html)

`middle.py` 编译原例并检验结果；`middle_extra.py` 的独立 Python 预期与 C 输出比较，参数数量覆盖 0、1、4、12，另有 10,000 个参数与操作系统单参数上限实验。过大的 exec 参数返回 E2BIG，不能写成“C 程序自己崩溃”。未重设 while 下标会跳过循环；遗漏递增的循环在本例中保持 `i=0`，静态不变式说明它不能到达正常终止条件，外部限时退出 124 是另一个独立的 TIMEOUT 观测。

`argv[0]` 是调用名称，用户首个参数是 `argv[1]`；只访问 `0 <= i < argc`，`argv[argc]` 是空指针而不是可打印字符串。把字符串指针从 argv 赋给 states 只是复制地址，未复制字符；因此需同时限制目标容量，并保留被指向对象的生命期。实验在交换指针后恢复 argv，避免后续测试意外依赖修改。`NULL` 表示空指针常量；某次 glibc `%s` 打印 `(null)` 不能推广为 ISO C 的保证。

倒序用 `i=argc; i>0; --i` 后访问 `i-1`，避免第一次访问 argc 和 unsigned 下溢。`break` 退出最内层循环或 switch。多 case 共用语句与缺少 break 引起的穿透不同；Y 的 break 若移入 if，条件假时会继续进入下一 case，已用实际输出证明。大写转小写的字符差值版只承诺 ASCII 英文字母，通用分类函数必须把普通 char 先转成 unsigned char。switch 和 if 两版都处理所有参数，独立 Python oracle 逐字符确认元音与 Y 规则。

## 14–16：函数、指针与结构体

函数原型保证调用处知道参数和返回类型。删去声明的测试以编译诊断记录；给字符串函数传 NULL 的负例另做运行时检查。合并 `can_print_it` 是减少一层无必要封装，不改变判断条件。长度版本接收显式 `n`，即使中间含 NUL 也处理 n 个字节；字符串版先用 strlen，调用者必须提供可终止的字符串。ctype 函数的参数域是 EOF 或 unsigned char 的值；对全部 256 个字节进行了比较，不能把负的 signed char 直接传入。

`a[i]` 与 `*(a+i)` 等价仅在合法对象范围内。指针加 1 按所指类型大小推进；本机 int 为 4 字节，实测地址差为 0、4、8、12、16。`%p` 的实参转换为 `void *`；这些数值受 ASLR 影响，不作为固定答案。数组在多数表达式中退化为指针，但 `sizeof array` 与 `sizeof pointer` 不同。四个独立函数覆盖数组/指针配合 for/while 的遍历，名字与年龄输出逐项对照；反序年龄也有独立预期。

栈上 `struct Person p={...}` 用 `p.field` 访问，可按值传入函数；不需要堆分配，不能把栈对象交给 free。含指针字段的结构体按值复制仍是浅拷贝。本练习栈版本采用自含字段/受控字符串，不让函数返回局部变量地址。堆版本要求创建成功后才使用，并明确对象和 name 的释放责任；漏掉全部释放和只漏 name 都由 Valgrind 拒绝。

### 函数格式比较（LCT-14-X04）

GNU 风格通常把函数名和函数体左花括号放到独立行，函数体缩进两空格；Linux 内核风格使用 8 列 tab，函数左花括号单独一行，控制语句左花括号通常与条件同一行。本项目遵循各目录现有风格，避免无意义的混排。[GNU Formatting](https://www.gnu.org/prep/standards/html_node/Formatting.html)、[Linux coding style](https://www.kernel.org/doc/html/latest/process/coding-style.html)

原文的旧式 K&R **参数定义语法**，如 `f(x) int x; { ... }`，与今天俗称 K&R 的**花括号风格**不是同一个概念。前者缺乏现代原型的清晰类型检查，本项目使用 `int f(int x)`；不能因为代码采用同行花括号，就说它使用了过时的函数参数语法。

## 17：文件数据库与栈

先执行原数据库 CRUD。此平台原 `Address` 大小 1032 字节：两个 4 字节 int，加两个 512 字节 char 数组；100 行文件为 103200 字节。直接写结构体会把 ABI 布局、对齐、字节序固化到文件中，移植到其它机器未必兼容。长输入的 strncpy 未终止和负 ID 越界分别被实际复现。

派生 [database.c](../solutions/continued/database.c) 使用明确的小端格式，头部 32 字节：8 字节标识、8 字节字段宽度、8 字节行数、8 字节 FNV 校验。每行 `1 + 4 + 3*w` 字节，分别保存设置标志、年龄和 name/email/city。文件尺寸为 `32 + rows*(5+3*w)`，独立 Python 解包与重新计算校验值；不再依赖编译器结构体打包。FNV 用于意外损坏检查，不是密码学认证。

width=1、8、32、513，36 步确定性操作、查找、重复写入、删除、截断文件、错误校验、非法数字和整数溢出均有测试。字段最多保存 w-1 字节并明确补 NUL，截断是声明的接口行为。所有错误经过统一清理路径。Python 测试器遇不匹配即失败，符合原题允许的 Python 自动化替代。global 连接版本也实跑，但它增加隐式状态、不利于重入和同时打开多个库，显式连接参数版本是主交付。

64 MiB RLIMIT_AS 下的容量探测得到本次最大成功 326241 行，下一行失败；这是指定字段宽度 64、当前地址空间及分配器下的观测，不是机器或算法的普遍最大值。栈实现使用 capacity=8 的数组和顶部下标，push/pop 均先检查满/空；C 与 Python 两种实现对 2000 步操作逐项核对。LIFO 是最后入栈者最先出栈，区别于先进先出的队列。

## 18–20：回调、对象组合与诊断宏

比较回调的函数类型必须匹配；不匹配回调由编译器拒绝，NULL 回调产生实际非法访问。用关系比较生成 -1/0/1，避免 `a-b` 的有符号溢出。bubble 与 insertion 两种算法接收同一比较函数，0–64 个元素、正反序与 INT_MIN/MAX 合计 260 组，用 qsort 独立比较。书中的 strange_order 不是一般严格弱序，不把其特定输出当作正确的通用排序。

从 ELF64 符号表找到函数地址及所属 section，再换算文件偏移，逐字节与运行时读取的 25 字节比较；该操作限定 AMD64 ELF/Linux，不是可移植 C 技巧。xxd 编辑副本中等长的 USAGE 字串，重运行观察变化；没有修改原始二进制或随机破坏用户程序。

原游戏能运行但有图对象泄漏，保留原例和 Memcheck 记录。派生游戏用公共 object/actor 层及独立 Map/main，分别建造六房间三怪物和第二个三房间游戏，固定种子 260719。地图拥有房间数组，连接只是借用指针，不沿环形连接递归释放；析构每个对象恰一次。五个命令脚本在 Valgrind 下零错误，make clean 确认删除 object.o，然后重建再验。

NDEBUG 在源文件顶端定义和从编译器 `-D NDEBUG` 定义分别实测，debug 日志消失而 check/错误路径保留。宏中的 `__FILE__`、`__LINE__`、`__func__` 定位失败上下文；多语句宏应放在 `do { ... } while (0)`，避免调用方 if/else 被破坏。不要用仅在 assert 参数中执行的副作用实现必要逻辑，因为 NDEBUG 可以移除 assert。

## 21–22：类型、存储期与作用域

[教学卡片](21-flashcards.md)列出类型、运算符与控制结构。`types.c` 实测 30 种 exact/least/fast 整数类型族及 intptr、intmax、size、ptrdiff，Python 按字节数验证本机范围，另保存实际预处理器宏。exact-width 类型、intptr_t 是条件提供，不能承诺每个 C 实现都有；本机 intmax_t 也不等于能表达 GCC 所有扩展 __int128 值。

const 约束通过该 lvalue 写入，不表示原本可修改对象会全局冻结；volatile 访问必须按实现约定保留，不提供原子性、线程同步或通用内存屏障；register 是存储类提示并限制取地址，不保证物理寄存器分配。[GCC volatile 文档](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html) C 的调用始终按值；传入指针复制的是地址，解引用才能改调用者对象。

多翻译单元实验中 extern 声明共享一个定义，文件 static 隐藏名字，函数 static 保存跨调用的值。去掉 extern 在 GCC 默认 fno-common 下产生多重定义；尝试访问隐藏变量产生未定义符号。返回活着的 static 对象指针可合法访问对象，不是绕过寿命规则；返回栈局部地址则不成立。128 KiB 进程栈限制下实际递归耗尽并保存 GDB 回溯，未修改全局栈或 ptrace 安全策略。

## 24–25：输入、格式与变参

原输入例程分别运行正常输入及错误年龄/颜色/浮点数。安全版先读有界行，再用 strtol/strtof 检查结束指针、范围与有限值；仅用 atoi 无法可靠区分转换失败与合法零。拒绝超长名字、缺失行、数值尾随垃圾、溢出、NaN。`scanf` 等价于从 stdin 读取的 `fscanf` 形式；`%50s` 写入 100 字节数组本身不溢出（最多 50 字节加 NUL），但跳过/终止于空白并把末尾换行留给后续读取，实测下一字节为 10。

逐字符文件读入使用 fscanf 的 `%c`，capacity=0 明确报错且不写，capacity>=1 最多读 cap-1 并终止。cap=1、2、8、33、100、EOF 与边界哨兵都验证。所谓“无论容量多少都写 NUL”在容量为零时不可能，必须先声明有效缓冲区契约。旧 gets 仅在隔离故障程序中使用，并以真实 256 字节输入复现无界写入；主交付不存在 gets。

`char **out_string` 让被调函数把新分配地址写回调用者，`*out_string` 是地址，`**out_string` 是该地址首字符；所有权转移后由 main 释放。va_start/va_arg/va_end 按约定类型依次取参，默认提升使 char/short 按 int、float 按 double 传入；运行时无法普遍发现调用者少传一个参数。负例展示该契约破坏，正确版本对 EOF、长行和字面量错误清理。tiny_print 只实现 `%d/%c/%s/%%`，main 已使用它，不宣称完整 printf 替代品。

## 27–30：防御式编程、构建、动态库与测试

防御式检查次序是先验证参数域，再做可能溢出/越界的运算；明确输入长度、输出容量、所有权、失败状态，并让测试覆盖错误路径。练习 27 原文缺少 `#undef` 的 #，原样编译失败保留；修复副本后仍发现所谓 safercopy 在判断之前计算 `INT_MIN-1`，以及只在容量末尾补 NUL 导致未初始化间隙被读取。新的 bounded_copy 在运算前检查，memmove 明确支持重叠，紧接有效数据终止；ASan/UBSan 和容量哨兵验证边界。

外部代码复查选择固定版本官方 xxd 的列宽参数检查、读写错误传播与 Makefile，实际测试非法列宽、13 字节切片和不存在文件。在已审查范围未发现新的确定缺陷，故没有捏造 bug 或发送补丁。可疑点不是已证实漏洞；整个项目也未因此获得“无 bug”结论。

构建骨架按 src/include/tests/build 分离，库无 main，测试程序链接库。静态库保存对象供链接时选择，PIC 共享库可在运行时 dlopen；dlsym 后应检查 dlerror 并匹配函数签名。实际运行正常路径、错误库名/符号/调用、损坏 ELF 头及 RTLD_NOW/LAZY。长度版本处理内嵌 NUL 和 0xff，有界输入不依赖 strlen。

BADFUNCS 是文本正则，不理解 C 语义：行首及间接调用可能漏检，注释/普通文本可能误报，不能当作安全证明。四个非空 minunit 测试实际执行；另外插入故意失败测试，make 返回失败，确认测试器不会吞错。清理后的骨架移除 ex29 内容，再复制构建通过。C 版 runner 用 fork/exec/wait 获取退出状态，测试全部成功、至少一个失败和空测试集合；空集合拒绝，防止“零条测试全通过”。

## 31：GDB、附加与 core

原例忘记递增，断点观察 i 连续为 0；设置 i=200 后它正常退出。真实 attach 到已经运行的进程，再改变变量并继续运行，区别于让 gdb 自己启动 inferior。当前 WSL 无 Yama ptrace_scope 文件，使用正常同 UID 调试；有 Yama 的目标程序只授权具体调试器 PID，未降低全局安全配置。

崩溃例在 i=5 处触发 SIGSEGV。通过 GDB 显式 generate-core-file 保存该停止时刻，再用另一个 GDB 读取 core 检查变量和回溯；属于调试器生成的 core，未声称修改全局 core_pattern 后内核自动落盘。目标环境特意最小化，core 不含无关用户程序环境。

VS Code C/C++ 扩展是可选图形前端，可用 GDB，提供断点、调用栈、变量/监视、core 与远程调试；命令行 GDB 更便于保存可重放脚本和在无 GUI 的环境运行。GUI 不是只能本地使用，原书“对服务器没有意义”的概括不适用于现代远程调试。本项完成基于[官方功能文档](https://code.visualstudio.com/docs/cpp/cpp-debug)的比较，**没有运行 GUI 调试会话**。

## 32–33：链表不变式、所有权与排序

单链表每节点只有 next，元数据较少，适合单向流式遍历；给定前驱时插入/删除 O(1)，只有目标节点时通常仍需 O(n) 找前驱。双链表另有 prev，给定有效节点可 O(1) 删除，支持反向遍历和双端操作，但占用更多内存且维护更多不变式。按下标定位两者均为 O(n)，节点分散导致缓存局部性差；不能把“节点已找到后删除很快”说成“任意查找删除都是常数时间”。连续数组可 O(1) 索引，批量扫描通常更友好，插入删除中间则需搬移。

不变式包括 count 与可达节点数一致、head.prev=NULL、tail.next=NULL、相邻节点互为 prev/next，正反遍历都到达正确端点。3000 步参考模型测试逐次检查这些条件，另测空表/单节点/端点删除。copy 复制节点但借用 value；concat 转移节点所有权并使源表为空；split 转移后半节点并修复双方端点。clear_destroy 只用于本表拥有且恰能释放一次的堆 value，不能对多个共享 value 的副本分别释放内容。

原归并示例在现代 GNU17 -O0 下遇到非 static inline 外部定义问题，先保存链接失败，再将辅助函数改 static inline。原单元测试能过仍有内存泄漏：递归中间表头没有全部释放，0/1 节点分支又会直接返回输入，使调用者难以统一所有权。修正版约定每次返回新的节点副本，释放递归中间头/节点，原输入和借用 value 不受影响；这些属于明确修改原例的 PASS_ADAPTED。

稳定性用 `(key, original_index)` 的参考顺序验证：相等 key 保持原输入先后。0–64 长度、重复值、顺/逆序共 260 组，不只检查是否递增。自底向上归并按 1、2、4…长度有序段迭代归并，维护 prev/tail，无递归和节点复制；比较相等时取左段保持稳定。排序链表麻烦的原因是无法 O(1) 取中点、交换时要维护连接及端点、分割/合并伴随所有权和空表边界；选用顺序归并能适应这一结构，数组索引算法不能机械平移。

### 实测性能与边界

![链表构建与排序实测](../figures/list_benchmark.png)

原始值在 [JSON](../../../../reports/E3_list_benchmark.json) 和 [CSV](../figures/list_benchmark.csv)。固定种子 `260733+n`，n=32/128/512/2048，各长度四种方法输入相同。每个点累计至少 3 秒，单批次、无置信区间；WSL2 非隔离，GCC11 -O2，4 vCPU、2 GiB 上限，顺序运行。计时包括构建结果所需分配/复制及丢弃输入的清理，结果校验与最终析构在计时外。它比较端到端构建有序链表成本，不是只测比较函数或纯 sort 内核。

| n | 冒泡 μs | 复制式归并 μs | 自底向上归并 μs | 逐次有序插入 μs |
|---:|---:|---:|---:|---:|
| 32 | 2.292 | 9.840 | 0.759 | 0.810 |
| 128 | 34.125 | 51.526 | 3.563 | 10.588 |
| 512 | 631.852 | 254.776 | 23.556 | 147.425 |
| 2048 | 10927.231 | 1243.194 | 211.250 | 3184.189 |

本次小规模下复制/分配的常数成本使复制式归并慢于冒泡；扩大到 512/2048 后渐近优势显现。n=2048 冒泡比较 4118564 次，两种归并均为 19915 次，有序插入为 1040499 次，与 O(n²) 和 O(n log n) 趋势相符。两条归并比较次数曲线重叠是实测相同，不是漏绘。逐次有序插入适合需要持续保持有序的小集合，最坏构建成本仍 O(n²)；本次最快方法不构成全局最优证明。以上是软件性能，不能转称芯片面积、时序或 PPA。

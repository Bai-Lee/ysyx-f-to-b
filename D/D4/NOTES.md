## 看到 C 表达式，先问它落在哪个机器对象上

常量要进入寄存器；变量可能在寄存器、静态区、栈或堆；读写内存依赖地址、宽度和扩展规则。课件先用“变量放在内存，需要时读入寄存器”的模型帮助理解，优化编译器也能使局部变量完全不占栈空间，不能把教学模型当成所有编译结果的规定。

装入 32 位常量时，ADDI 的 12 位立即数要符号扩展。以 3000 为例：先 LUI 得到 4096，再 ADDI -1096，结果才是 3000。这里 ADDI 的源必须是刚得到高位的寄存器；课件展示的 `addi r,zero,...` 若用于这两条连续指令，就会丢弃 LUI 的结果，应读作 `addi r,r,lo12`。例如 `0x1234=4096+564`，不需要负的低位补偿。

RV32 的一个寄存器装不下完整 64 位整数，可以把低、高 32 位分别保存。做 64 位加法时，先加低位，再用无符号比较判断是否产生进位，最后把两个高位与进位相加。这里的进位是跨字算术的一部分，不能混同于 C 有符号溢出检查。

| C 层问题 | 机器级观察入口 | 易错点 |
| --- | --- | --- |
| 字节/半字读写 | LB/LBU、LH/LHU、SB/SH | 读出的符号扩展不同；存储只取低位 |
| `a+b` | ADD/ADDI | 相同硬件位运算不代表 C signed/unsigned 溢出规则相同 |
| 比较与右移 | SLT/SLTU、SRA/SRL | 有符号性影响指令选择 |
| if/else | 条件分支与目标 PC | 分支布局可倒置，源程序顺序不等于机器码顺序 |
| switch | 比较链、跳转表或结果表 | 选择取决于密度和优化，不保证总有跳转表 |
| 循环 | 条件跳转和反向控制流 | 编译器也可能展开或直接算出结果 |
| 数组访问 | 基址 + 下标 × 元素大小 | 步长不是固定 4；越界仍可能是 C UB |
| 结构体成员 | 基址 + 编译器确定的偏移 | padding 使大小不一定等于成员大小之和 |

## 函数调用需要共同约定

CALL 的关键是保存返回地址并改变 PC；返回通常是 JALR 到 ra。ABI 还规定参数、返回值、调用者保存/被调用者保存寄存器和栈的使用。普通 RV32 整数 ABI 用 a0–a7 传整数参数；D8 的 ILP32E 只有 a0–a5，不能直接套用 8 个参数寄存器的图。超过寄存器容量的参数放到栈；宽值或大结构体还需要成对寄存器、隐式地址或内存传递。

栈帧使递归中的同名局部变量拥有不同存储位置。调用子函数前若本函数仍需要旧 ra，就必须保存它；调用之后仍需使用的临时寄存器值也要按 ABI 处理。尾调用可直接跳转到另一个函数，复用本次调用的返回地址，因而 ftrace 中“进入 A、最后从 B 返回”未必是错误。D7 的 `outer -> tail` 用例直接演示这一点。

指针保存地址。`p[i]` 的地址等于 `p+i*sizeof(*p)`；负下标是否合法取决于最终地址是否仍在同一个数组对象范围内。结构体各成员按各自对齐要求排布，整体大小再按最大对齐取整，保证结构体数组的后续元素也能对齐。联合体成员共享起始位置，但其整体尺寸仍可能需要尾部填充；跨成员解释位模式还必须检查语言规则与目标表示，不能只凭一次输出推定可移植性。

浮点调用约定、RV64 和硬件浮点指令在课件中用于对照。本阶段的 NEMU/NPC 没有据此实现 F/D 扩展；需要浮点的 C 程序由目标工具链的软件浮点支持实现。

## C 规则与 ISA 规则的边界

即使 RISC-V ADD 会截断到低 32 位，C 的 signed 加法溢出仍不能据此合法化。移位负数、移位量达到类型宽度、有符号左移结果不可表示、整数除零，都要分别按 C 规则审查。D3 的指令边界测试用汇编构造 ISA 输入；D1/D5 的宿主测试用 sanitizer 检查 C 实现，两类证据回答不同问题。

建议阅读顺序：常量与字节访问 → 有/无符号运算 → 分支循环 → 调用约定与栈 → 数组结构体 → UB。每一步同时查看相应 C、反汇编和寄存器/内存变化；可用 D2 的 `si`、`info r`、`x` 和 D7 的 trace 练习。

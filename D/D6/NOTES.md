# D6：事件、综合和工艺库的证据链

本记录对应 [D6 v26.07 原文](sources/D6.md)。仿真语义依据 IEEE 1364-2005 第 11 章；综合约束依据 IEEE 1364.1-2002 第 5 章和附录 B。二者版本、用途不同，不能混称为同一本标准。PDF 的原始文件、SHA-256、页码提取及两页渲染证据在 `temp/D6_pdf` 和 `artifacts/D6/standards`；原 PDF 保持不变。

## 1. 先给事件排序，再解释波形（M001–M005、M014、R001–R005）

初值 `(a,b,c,d,e)=(1,2,3,4,5)`，同一个时钟边沿触发的语句依次是：

```verilog
b=a; c<=b; d=c; e<=d; a=e;
```

执行 `b=a` 后 b=1；`c<=b` 此刻采样 1，排入 NBA 队列，但 c 仍为 3；于是 `d=c` 得到 3；`e<=d` 采样 3，等待 NBA；最后 `a=e` 读旧 e=5。活动事件完成后再更新 NBA，稳定结果为 **(5,1,1,3,3)**。这里的“下一状态”是当前边沿处理完的状态，不是等到下一个物理时钟才写 c、e。

若两个 always 分别执行 `a=b`、`b=a`，旧 `(a,b)=(0,1)` 时，允许先后次序产生 `(1,1)` 或 `(0,0)`。都改成 NBA 时，各自先读旧值，最后得到 `(1,0)`。这个例子因而消除了跨进程旧值采样竞争，但不能推导出“任意使用 NBA 的多进程代码都没有竞争”。

把 `$display` 改成 `$strobe` 只改变观察时机：display 在执行它的当前事件区读值，strobe 在当前时刻其他更新完成后观察。它不会修复被观察电路自身的竞争。`events.v` 的 display 允许看见 0 或 1，而 strobe 必须看见最终的 1；我们检查后者，不把本次 Icarus 恰好选的次序当成语言的唯一结果。

| 原页说法 | 结论与原因 |
| --- | --- |
| `#0` 强制放到当前时刻末尾 | 不准确：进入 inactive 区，仍先于 NBA；实验直接检查此时 NBA 目标未更新 |
| 同一 begin/end 多次 NBA 结果未定义 | 错：同一进程保持语句次序，最后一次对同一完整变量的更新生效 |
| 组合 always 不能用 NBA | 语法上可用；可能引起额外 delta、重触发和旧值传播，工程上通常采用阻塞赋值 |
| 多个 always 绝不能写同一变量 | 仿真语法并非一律禁止；可能竞争或不可综合，应审查触发条件与单驱动要求 |
| display 有时输出错误所以不建议用 | 它正确输出其执行时可见的值；需要边沿最终状态时应改变采样位置或使用 strobe |
| display 无法输出 NBA 结果 | 太绝对：NBA 之后的事件或后续时刻执行 display 可以看见结果 |

对 `a=0; a=1;` 与另一个进程 `b=a;`，保持第一个进程内部次序的交织有三种，b 可为 0 或 1。若不指定 a 的初值，第一次触发前还可能读到 X。独立的有限交织枚举写在 [event_model.json](results/event_model.json)，实际仿真只是对其中允许行为的佐证。

Verilog 语句在仿真器中是事件，不是直接串行执行的 C 语句；综合器又会把受支持的描述转换为电路。正因此，仿真、综合和真实电路是三个需要衔接验证的层次。课件中“90%/10%”一类编码经验描述未附统计样本，本工程不把它当故障概率测量。

## 2. Verilator 如何执行流水灯（M002）

`light.v` 的端口 `clock/reset/led` 对应生成的 `Vlight.h`；内部 count 对应 root 结构中的 `light__DOT__count`。`eval()` 驱动生成的求值过程，在 `Vlight___024root__0.cpp` 中可看到：

1. `__Vtrigprevexpr___TOP__clock__1` 保存旧时钟，当前 clock 与旧值构成上升沿检测。
2. `_eval_act` 把触发标记转给 `__VnbaTriggered`。
3. `_eval_nba` 先用旧 led/count 计算临时 `__Vdly__...`，再统一写回成员。
4. reset 时 led=1、count=0；计数为 0 时旋转 led；count 达 5000000 时归零，否则加一。

这解释了为什么宿主必须先设置输入再调用 eval，也解释了 NBA 旧值读取如何映射到 C++ 临时量。生成符号名随 Verilator 版本可能变化，当前文件保存在 [results/verilator](results/verilator)。

实际 ECC 的 `Synthesis.log` 与 `yosys_synthesis.tcl` 在 `results/pvt/*`。此版本先读源文件并做 coarse/fine synth、必要的 flatten、share/onehot/muxpack 等优化，再进行 simplemap/techmap、触发器和锁存器映射、ABC、常量单元映射、清理和最终 netlist 输出。ABC 使用 `DELAY 4`，目标由 100 MHz 时钟及脚本的 0.95 slack margin 得到 9500 ps；它只是综合优化目标，最终仍需查看 STA。脚本还执行 setundef，说明对设计中的 X 不可依赖“上板仍为 X”的直觉。

门合并通常省面积但增加扇出，是否降频要结合负载、驱动和布线。`techmap` 在 Yosys 文档中的广义映射也包含从字级到门级；课件将“映射到具体工艺库”单独称为工艺映射，两种术语范围不同。综合器质量、FPGA 与 ASIC 流程的速度比较依赖设计与工具，本工程没有进行商业工具横向评测。

## 4. 综合标准第 5 章与附录 B（M013、M015）

已读取 IEEE 1364.1-2002 第 5 章（PDF 物理页 15–24、正文页 6–15）和完整附录 B（物理页 102–109、正文页 93–100）。以下是依据条款的解释，不是对现代 Yosys 的 IEEE 全面符合性认证。

第 5 章分别约定组合逻辑、边沿触发、异步复位、锁存器、三态、X/Z、ROM 与 RAM。组合过程中每条路径应给输出赋值，否则保存旧值就会推导锁存器；敏感列表在综合中可能不参与硬件含义，但仿真仍受它约束。边沿事件和异步置位/复位的判断极性必须一致。时序块可使用阻塞赋值计算临时量，再用 NBA 更新状态，但同一个状态变量混用两类赋值不属于该标准支持的写法。Z 应通过受支持的三态模板表达，不能任意经中间变量传播后就假定有三态器件。X 在综合中可能是 don't-care。ROM 可按 case、受限初始化或 $readmem 模式表达，RAM 的端口、读写时序和映射资源还要匹配具体工具/工艺。

| 附录项 | 应检查的风险与例子 |
| --- | --- |
| B.1 不确定行为 | 同边沿两个进程阻塞交换变量；活动事件次序改变结果 |
| B.2 full_case / parallel_case | 前者承诺覆盖全部情况，后者承诺分支互斥；错误承诺会使综合舍去仿真中仍有的行为 |
| B.3 ifdef | 仿真分支 `y=a`、综合分支 `y=b` 不是同一规格；必须检查两套条件编译 |
| B.4 敏感列表不完整 | `always @(a) y=a&b` 在仅 b 改变时不更新，综合门却响应 b |
| B.5 临时量赋值顺序错误 | 先 `y=t` 后 `t=a&b` 会读旧 t，综合组合展开却可能直接得到新表达式 |
| B.6 同时异步置位/复位 | 同时有效及解除先后顺序涉及优先级和目标触发器行为，不能只测单独复位 |
| B.7 函数隐藏状态 | 函数返回值并非所有路径赋值时可能推导锁存器，函数调用外表不能掩盖存储行为 |
| B.8 casex | 输入 X 参与通配，可能选中本不确定的分支并掩盖错误 |
| B.9 casez | Z 也可成为通配；要区分已知二进制重叠分支与未知/高阻输入 |
| B.10 赋 X | 仿真 X 与综合为优化而选定的 0/1 不等价；不可把未实现行为藏进 X |
| B.11 声明初始化 | 模拟初值与目标芯片上电/复位能力不同；ASIC 不会自动拥有任意寄存器初值 |
| B.12 延迟 | RTL `#2` 改变仿真时间，常规综合会忽略它，不能据此设计硬件延迟 |

`mismatch.v` 实际演示敏感列表、临时量顺序、casex/casez 和延迟差异，`events.v` 验证事件次序。对附录 B.9 的代码还需谨慎：若没有 parallel_case 承诺，二进制 11 按 casez 顺序选第一个匹配项，本身不能推出一定仿真/综合不一致；Z 通配才是另一类风险。本工程记录这一推理边界，不擅称发布了官方勘误。

## 5. 流水灯的时序和功耗（M016、M017、M026）

三个独立工作目录分别使用 TT/SS/FF 库，RTL、LEF、100 MHz 时钟和 DELAY 4 策略保持相同；每个角都重新综合，因此门尺寸选择也可能变化。执行使用兼容的 Yosys 0.68+118 与原有 ECC，限制单个流程、两个 CPU 亲和核、2.8 GiB 进程组 PSS。没有改全局环境。

| LIB 条件 | 面积 μm² | setup WNS ns | hold WNS ns | 工具频率估计 MHz | 动态功耗 μW | 漏电 μW |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| tt / 1.20 V / 25°C | 625.52 | 9.419 | 0.137 | 1720 | 54.7681 | 0.0780479 |
| ss / 1.08 V / 125°C | 637.56 | 8.971 | 0.246 | 971 | 40.3029 | 0.8693549 |
| ff / 1.32 V / -40°C | 636.72 | 9.652 | 0.082 | 2876 | 71.4548 | 0.5802495 |

证据见 [D6_pvt.json](../../reports/D6_pvt.json)。时钟周期是 10 ns，工具用关键寄存器路径余量推算的频率不是在该新频率下重新约束、完成布局布线后的 signoff。SDC 只实际创建 clock；`clk_io_pct` 变量没有生成输入/输出延迟，故外部 I/O 时序未完整约束。ZeroWireload 不包含实际布线寄生。不能把表中频率当作实物芯片保证值。

power.rpt 的 TT 内部功耗为 54.2602 μW，净切换功耗 0.5079149 μW，相加为动态功耗；再加 0.0780479 μW 漏电得到约 54.8461 μW。报告注明 Analysis Effort=low、ZeroWireload；本次未提供 VCD/SAIF，是工具默认活动模型，报告未披露足以重建全部输入活动率的数值，因此不编造“所有节点 10% 活动”之类条件。它不是流水灯实测功耗，也不能凭 PVT 表分离工艺、电压、温度各自的因果贡献。

降温可能改善某些条件下的速度，但必须查询相应库表，不能把温度效应当无条件单调规律。tt 是典型点而非几何角点；ss/ff/sf/fs 描述两类管子的模型组合，不是每颗芯片的精确身份。课件把 i3/i5/i7 与三个工艺角一一对应的故事未给可核验证据，本工程不把它作为分析依据。后端需按工艺要求选角，不能仅按“某角概率低”排除规定角落。

## 6. 从工艺文件读数（M018–M025、M028–M029）

[D6_pdk.json](../../reports/D6_pdk.json)记录原 CDL/LIB/LEF 路径与哈希。LIB 的时间单位为 ns、电容为 pF、漏电为 nW；LEF 尺寸采用 μm。LEF 中有 7 个 TYPE ROUTING 项：MET1–MET5、T4M2、RDL。按工艺命名讨论“六层主互连加再布线层”时，应与这 7 个 routing 定义区分，不能只数名称 MET 开头的项目。

| 层 | 方向 | PITCH μm | WIDTH μm |
| --- | --- | --- | --- |
| MET1 | 横向 | 0.2 / 0.2 | 0.09 |
| MET2–MET5 | 纵横交替 | 0.2 / 0.2 | 0.10 |
| T4M2 | 纵向 | 0.8 / 0.8 | 0.40 |
| RDL | 横向 | 5 / 5 | 3 |

从宽度、pitch 可推测低层更密、上层更适合较长互连，但时钟/电源究竟走哪一层还取决于具体后端配置；这里不把推测写成设计规则。标准单元高度 1.4 μm，MET1 pitch 0.2 μm，因此轨道数为 1.4/0.2=7。SITE core7 为 0.2×1.4 μm；最小 FILLER1H7L 也正好是一个 SITE，便于填满最小放置栅格。

NAND2X1H7L 是 0.8×1.4=1.12 μm²；数据 I/O 单元 P65_1233_PBMUX 是 65×130=8450 μm²。后者约大 7544.6 倍，不能用核心门的面积尺度估算 pad。I/O 包含驱动、保护和外部连接约束；这个几何比较本身没有测量其电气性能。

NAND 的两个 nMOS 串联形成只有 A=B=1 时导通的下拉，两只 pMOS 并联提供互补上拉。OAI22 的下拉是 `(A0|A1)&(B0|B1)`，上拉是其对偶，故输出为该式取反。AOI221 对应 `!((A0&A1)|(B0&B1)|C0)`，和 LIB 的展开式逐组合一致。

## 7. 背景与范围收尾

时钟专用单元、扫描单元、常量单元和 filler 各有用途，不宜让一般逻辑门替代其物理角色。PDK 的 LIB、LEF、CDL、Verilog、GDS 描述同一单元的不同侧面，彼此不能互相替代。公开发布范围随固定版本而定：课程早期文字称 GDS 未开放，当前锁定本地导出实际含 gds 目录，使用状态以这个固定快照和许可为准。

物理流程依次涉及 floorplan、IO/宏位置、电源、布局、CTS、布线、寄生提取、时序、DRC/LVS，再到制造、切割、封装和板级运行。D6 本次只做综合后评估；E 阶段的既有版图结果保持独立，不能充当 D8 新 CPU 的物理 signoff。不同阈值电压任务原文 M027 只有 todo，按既定范围排除，不补造作业。多轨道库能否混合要由放置行、供电和工具规则决定，不能把课件的一般化表述当所有现代工艺的禁止规则。

复验入口：`run_logic.py`、`run_pvt.py`、`analyze_pdk.py`。其中 run_pvt 只在命令和输入输出哈希匹配时复用已有证据；复用不冒充新一轮运行。

# D3：把程序落实为 RV32IM 状态转移

范围来自 [D3 原文](sources/D3.md) 与 PA2.1、PA2.2。这里完成的是 TRM 所需的 RV32I 整数指令、M 扩展和主机退出约定；不是含特权级、异常委派、MMU 和中断的完整机器。源文件仍保留原版权，新增实现与独立验证分别位于 `D/nemu_overlay` 和本目录。

## 先理解一条指令怎样改变状态

状态可写成 `(32 个 GPR, PC, RAM)`。先从旧 PC 取 4 字节，再解析 opcode、rd、rs1、rs2、funct3、funct7 和立即数，计算结果，最后写回 rd 与下一 PC。顺序执行的下一 PC 是旧 PC+4；分支、JAL、JALR 会选择不同的下一 PC。x0 的写入必须丢弃，不能只是初始化为零。

以 `addi x5,x6,-1` 为例：I 型立即数的原始 12 位是 `0xfff`，扩展为 `0xffffffff`；先读旧 x6，做 32 位模加法，再写 x5。因此 rd 与 rs1 相同也能工作。分支立即数把指令中的分散位拼回 B 型位序，最低位补零，随后符号扩展；不能直接把某个连续字段当偏移。

完整调用链是 `main → init_monitor → sdb/批处理 → cpu_exec → execute → exec_once → isa_exec_once`。取指进一步经过 `inst_fetch → vaddr_read → paddr_read`，本阶段无 MMU，所以虚拟/物理地址按恒等关系处理；取指推进 snpc，执行设置 dnpc，外层再更新 cpu.pc。随后做 trace、DiffTest 和监视点检查。非法编码设置 ABORT；EBREAK 设置 END；监视点变化则停在刚完成的指令边界。snpc 是下一条静态指令位置，dnpc 是真正接下来执行的位置，两者只在顺序流时相同。

原框架的 INSTPAT 把位模式转换为 mask/key 再比较。本工程采用统一字段提取与 opcode/funct 分派，保留相同 ISA 语义；并非每增加一条指令就复制整个执行过程。阅读原宏时可用 GCC `-E` 展开，而不是手工猜嵌套拼接。寄存器名称也用一张表复用，避免原示例把 x7 错写成 s2、又在 x18 重复 s2 所造成的不可达分支；x7 应为 t2。

实现中的 `sext` 使用无符号算术，`signed32` 将 32 位位模式提升为有定义的 int64 值。这样能分别处理 SLT/SLTU、SRA/SRL、DIV/DIVU，而不把宿主 C 的有符号溢出当作客体 RISC-V 语义。移位量掩成低 5 位；乘法高半部先按所需符号性扩展到 64 位。

| 边界 | RV32 结果或处理 |
| --- | --- |
| `0xffffffff + 1` | 低 32 位为 0 |
| 有符号最小数除以 -1 | 商仍为最小数位模式，余数为 0 |
| 整数除以 0 | 商为全 1；余数为被除数 |
| JALR | 计算 rs1+imm 后清 bit 0；本机器取指仍要求 4 字节对齐 |
| LB/LH 与 LBU/LHU | 前两者符号扩展，后两者零扩展 |
| SB/SH | 仅修改指定字节，其他字节保持不变 |
| FENCE/FENCE.I | 本单核、无缓存解释器顺序执行；不据此声称支持缓存一致性系统 |
| EBREAK | 本实验运行时读取 a0，作为主机 GOOD/BAD TRAP；不是实现了完整调试异常 |

RAM 从 `0x80000000` 起，共 128 MiB，小端。地址检查覆盖完整访问区间，防止起始地址合法但尾部越界。宿主用 memcpy 搬运字节，避免未对齐指针强转造成宿主 UB。NEMU 的 RAM 模型允许非对齐访问；锁定的 Spike 配置会拒绝它。实际交叉验证程序采用严格对齐编译；不把这个执行环境选择推广成所有 RISC-V 机器的规则。

若把同一客体模拟器移到大端宿主，不能继续依赖当前 memcpy 后按宿主整数解释的假设，应显式按客体字节序组合/拆分多字节数值。若增加大端客体 ISA，则连取指和数据访存都要按该客体规则解释；“宿主大端”和“客体大端”是两个独立问题。伪指令也应通过原始编码或 `objdump -M no-aliases` 回到真实 ISA 指令，不能仅按别名猜功能。

## 怎样确认实现，而不是只看程序有没有结束

[边界测试](../../reports/D3_isa.json) 使用独立 Python 整数语义生成 2392 个预期结果，覆盖符号边界、移位、rd/rs1 重合、分支正负偏移、跳转和访存；执行时又与独立 Spike 比较 PC 和全部 32 个 GPR。6 类坏指令/坏地址及空镜像、超大镜像构成负对照。

[官方程序结果](../../reports/D3_official_tests.json) 包含 38 个 RV32I、8 个 M 指令测试及 35 个 C 程序，共 81 个。官方默认不选 `fence_i`、`ma_data`；FENCE 另有本工程的边界用例。`wrong` 单独运行，真实 BAD TRAP 必须使顶层 make 返回失败。原测试正文没有为通过而修改。

有三个容易忽略的实验边界。第一，比较 PC/GPR 并没有逐字节比较整个 RAM，未被后续程序读出的错误写入可能漏检。第二，有限测试通过不等于 ISA 全输入形式化证明。第三，早期裸机链接脚本把 build-id 放在低地址，导致 objcopy 生成巨大稀疏文件；修复链接布局并增加镜像容量检查后重测，失败尝试仍保留。

复验入口：`verify_isa.py`、`run_official.py` 及各 `artifacts/D3` 的 `run.json`。历史报告绑定当时二进制；后续 D7 增加跟踪后另做回归，不能把历史二进制哈希当成当前源码指纹。PA2.1 的原生显示/按键/声音环境在本次 D8 中重新核对，见 `D8_fceux_native.json` 与 `D8_native_keyboard.json`；并非仅引用 E 阶段旧截图。

# B3：用测量决定缓存设计

本文对应冻结的 v26.07 B3 公开任务。数值表由 [RESULTS.md](RESULTS.md) 和 `reports/B3_performance.json` 提供；原始日志、二进制 trace、综合脚本和波形保存在 `artifacts/B3`。程序使用真实课程 SoC 的 32 位 AXI/APB 框架；这里的 SDRAM 是引脚级数字功能模型，没有模拟电气噪声、保持时间分布或板级走线。

## B3-M001～M004：先明确计数，再判断瓶颈

令退休指令数为 $N$、CPU 有效时钟周期为 $C$、评估频率为 $f$。定义

$$IPC=N/C,\qquad CPI=C/N,\qquad T=C/f.$$

`simulation.cycles` 包含框架启动的少量额外周期；`performance.core_cycles` 是上述 IPC 的分母。报告同时保留二者，不把数值差异藏起来。`class_counts` 按算术、load、store、条件分支、jal、jalr、system、fence 分组；每条指令只归一类。`class_cycles` 把相邻两次退休之间的周期归给后退休的指令，各类之和等于 C。因而分类 CPI 是该程序中的退休间隔统计，不是单条指令的固有延迟。

IFU/LSU 各自记录请求、返回、请求到返回的周期和。IFU 缺指原因使用互斥分组，计数和加上返回周期数必须等于 C。性能计数器位于 C++ 仿真器和 `ifndef SYNTHESIS` 中，不把大计数器带入综合面积。每次运行核对指令分类之和、执行与访存数量、请求/返回配对以及所有周期恒等式。

多周期 CPU 的取指与数据访存不重叠，可以用 $S=1/((1-p)+p/k)$ 估计只改进占比 p 的部分。流水线的 IFU、LSU 与后端等待会重叠，不能把它们的计数直接相加，也不能把每个事件都当作独立可消除的周期。流水线分析另外列出假设和上界。

## B3-M005～M009：访存延迟与频率要一起变化

课程设备目标为 100 MHz，CPU 评估频率为 $f$，比例 $r=f/100\,\mathrm{MHz}$。模块使用 Q8 定点整数 `ratio_q`，使延迟目标为

$$D_{target}=\lceil D_{device}\,ratio\_q/256\rceil.$$

因此取整误差小于一个 CPU 周期。最终 325 MHz 对应 832，比例恰好是 3.25；400 MHz 的早期对照对应 1024。模块保持外部握手，不能通过提前返回来假装延迟变短。APB 测试包含不同实际设备等待时间和四种比率；AXI 测试包含读写并行、AW/W 到达顺序、1/4/8 拍读、响应反压和逐拍时间核对。故意多等一拍的实现必须被拒绝。

未校准的 400 MHz 仿真只用作错误性能模型的对照，不能据其 IPC 推断芯片速度。提高 f 后，固定物理时间的存储器等待会占更多 CPU 周期，所以 IPC 可能下降；总时间仍应看 C/f。频率提升的收益来自 CPU 本地计算与缓存命中部分，不能令外部存储器的纳秒延迟凭空消失。

寄存器堆和加法器分别在输入、输出插入触发器后综合，避免把不受约束的组合路径当成最高频率。其结果只解释局部路径，不是整颗 CPU 的 Fmax。独立 NPC 从 0x80000000 启动，使用快速功能存储器作回归；完整 SoC 从 Flash 0x30000000 启动，负责校准后的性能评估。

## B3-M010～M022：缓存、模拟器与总缺失时间

第一版是 16 行、每行一个 32 位字，即 64 B。最终缓存总共 4 行，每行 8 字、2 路、2 组，容量为 128 B；`LINES` 表示总行数，不能再乘一次路数。valid/tag/data 使用触发器阵列，二路替换等价于 LRU。填充完成且没有错误才设置 valid；失效与未完成填充冲突时，poison 阻止旧填充重新有效。

Flash、PSRAM、SDRAM 在明确地址范围内可缓存；片上 SRAM 和 MMIO 绕过缓存。MMIO 的读取可能有副作用，缓存后会改变设备行为。单元测试检查绕过次数、替换、每个块内字、跨块、CPU/内存反压和读错误；错误 tag 匹配实现会被独立数据函数抓出。

`cachesim.cpp` 读取完整的 20 字节二进制退休记录：PC、指令、下一 PC、数据地址、读写标记。每条 fence.i 使模拟缓存失效。多周期配置中没有错误路径取指，因此可以将同一 trace 的访问、缺失、绕过次数与 RTL 完全比较。流水线若产生错误路径预取，应使用实际取指 trace 作精确比较，不能把退休 trace 的缺失数强行当成硬件全部请求数。

同一 trace 批量探索容量、块大小、路数与布局。模拟器有独立手算的命中/冲突/失效例、WB/WA 脏替换例和截断输入反例。它是候选筛选工具，不是周期精确的系统模型，也不证明全局最优。

令 H、M、U 分别为命中、缺失和绕过次数，对应的请求到返回时间和为 $L_h,L_m,L_u$：

本多周期配置实测每次命中为一个周期，因此查找基线 $t_a=1$：

$$TMT=L_m-Mt_a,\quad AMAT_{cache}=(L_h+L_m)/(H+M),\quad \bar P_{miss}=TMT/M.$$

包含绕过请求的完整端口平均时间另外记为 $AMAT_{port}=(L_h+L_m+L_u)/(H+M+U)$。TMT 按课程口径表示缺失的额外等待，不能把缺失服务总和中的查找时间重复计入。早期机器报告的 `TMT_cycles` 曾表示包含查找时间的服务和，最终分析已明确区分这两个量；原始计数没有修改。流水线中的消费者反压还会改变请求到返回的观测时间，不能直接把它等同于纯 DRAM 延迟。不同块大小的快速模型用 1/4 字块校准后预测 8 字块，并量化误差；不会把估算直接写成性能实测。

较大的块可以利用空间局部性，也会减少同容量下的行数并搬运未使用的字。连续单字事务需要反复支付请求开销；INCR burst 共用一个读地址事务，并检查 beat 和 RLAST。最终只对 SDRAM 使用 burst，Flash/PSRAM 保留其兼容的单字访问。完整 SoC 的 AXI SDRAM 控制器支持 32 位总线、两 rank、四颗 x16 功能模型；小边界测试和八个独立的全 128 MiB 图样分别记录，不能相互替代。

## B3-M023～M025：布局、面积与未实现的 dcache

真实链接实验在代码前插入 24 B 填充，重建 ELF/BIN 后运行；程序的计算结果必须保持正确，计时打印与轮询导致的动态指令数可能少量变化。trace 平移估算只模拟地址布局，不重新执行程序，应与真实重链接结果分列。

缓存和流水线的最终选择受同一 Nangate45 典型库、同一 IO 约束及 25000 μm² 的标准单元面积限制。面积不是芯片版图面积，理想线网的时序也不是布线后的时序。旧缓存地址表达式曾在锁定 Yosys 中丢失高位；受影响的旧综合网表都保留为无效候选，不作为最终验收。修复后的候选在 RESULTS 中重新评估。最终网表还通过可复现命令调整两只 NOR4 的驱动强度，并逐项核对连接不变。

理想 dcache 假定所有可缓存数据访问命中，响应只需一周期。多周期模型的乐观节省为 $L_d-N_d$；MMIO/SRAM 绕过不应一起消失。有限 dcache 采用 WB/WA、LRU，计入缺失读整块与脏块写回；这是模拟估算，未实现 RTL。成本比较包括数据位、tag、valid、dirty、替换位、比较器和控制逻辑。当前面积余量很小，不能只数数据位就宣称放得下。更大的 icache 同样需要实测面积和整机收益；课程中的货币例子是假设，不是代工报价。

## B3-M026～M029：为什么必须 fence.i

store 更新主存并不会自动改变 icache 里的指令。自修改代码测试先缓存旧函数，再写入新指令；无 fence 的运行故意期望旧值，用以明确复现陈旧指令。加 fence.i 后必须执行新指令并通过 DiffTest。bootloader 的另一组测试先执行 NOP/ret 占位代码，再覆盖为目标程序；无 fence 时在目标入口看到旧 NOP 并产生 DiffTest 失败，有 fence 时正常执行。

fence.i 不只是清 valid：它必须在较老的 store 已完成后执行，并让后续取指无法使用此前保存的结果。临时预热/NOP 只存在于反例中；正常启动路径保留必要的 fence.i，不靠额外延时掩盖一致性错误。流水线内部旧指令的处理见 [B4 笔记](../B4/NOTES.md)。

## 阅读与选做边界

CoreMark/Dhrystone 等合成负载不能代表所有应用；本项目只报告具体 microbench test/train 的结果。覆盖率回答“某事件有没有发生”，不能证明所有事件组合均正确。FPGA 的器件频率、PHY、刷新和时钟比例与 ASIC 不同，校准模型也有边界。GPU shared memory 由软件显式管理，和本项目透明 icache 的语义不同。

动态调频可编程延迟寄存器、cache 的请求序列形式化证明没有实现；选做记录保留 NOT_RUN。数组/分散链表的小例是注明来源的合成地址序列，不冒充应用运行。二进制 trace 及其压缩快照保留哈希；未声称实现了全部可选 trace 压缩格式。
